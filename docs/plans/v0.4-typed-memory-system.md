# pg_recall v0.4 — Typed Memory System

## Context

pg_recall is being built as the cognitive storage layer for Chapterhouse, an MCP
memory server for AI coding agents. Rather than building a generic extension,
every design decision targets maximum effectiveness for this specific use case.

Chapterhouse currently has a type system spread across its PostgreSQL schema and
Qdrant vector metadata:

- **memory_type**: `factual`, `experiential`, `working`
- **scope**: `personal`, `org`
- **tier**: `core`, `index`, `state`
- **tags**: `text[]`
- **session_id**: UUID for episodic grouping
- **recall_count** / **last_recalled_at**: usage tracking

pg_recall's mneme schema currently has none of these. It has `workspace_id`,
`concept`, `content`, `embedding`, `confidence`, `access_count`, `last_access`,
`state`, and `search_vector`. The associations table is untyped — all links are
anonymous Hebbian co-activation weights.

v0.4 adds both **typed mnemes** (Chapterhouse-aligned metadata that influences
cognitive scoring) and **typed associations** (labeled, directional relationships
between mnemes).

## Embedding Dimensions — Configurable

pg_recall currently hardcodes `vector(384)` throughout the schema, functions,
tests, and recall SQL. Different Chapterhouse deployments use different embedding
models with different dimensions:

| Deployment | Model | Dims | Notes |
|------------|-------|------|-------|
| Homelab (Together.ai) | `Alibaba-NLP/gte-modernbert-base` | 768 | Best code retrieval on Together.ai; 8K context |
| Homelab (legacy) | `BAAI/bge-base-en-v1.5` | 768 | General-purpose; only 512 token context |
| Corporate (air-gapped) | `openai/text-embedding-3-large` | 3072 | Or 1024/256 truncated variant |

Hardcoding any single dimension would break cross-deployment compatibility.

### Design: Dimension Set at Schema Creation

v0.4 makes the embedding dimension a **one-time configuration** set when the
pg_recall schema is initialized. The dimension is stored in a `config` table
and referenced by all schema objects, functions, and indexes.

```sql
CREATE TABLE pg_recall.config (
    key   text PRIMARY KEY,
    value text NOT NULL
);

-- Set once during initialization:
INSERT INTO pg_recall.config (key, value)
    VALUES ('embedding_dims', '768');
```

A setup function handles initialization:

```sql
CREATE FUNCTION pg_recall.initialize(embedding_dims int DEFAULT 768)
RETURNS void
```

This function:
1. Validates the dimension (must be > 0, ≤ 4096)
2. Stores it in `pg_recall.config`
3. Creates the `mnemes` table with `vector(N)` using the configured dimension
4. Creates the HNSW index on the embedding column

Changing dimensions after initialization requires dropping and recreating the
schema — this is intentional. Mixing dimensions in the same vector space is
meaningless.

### Impact on Functions

Functions that accept embedding parameters (`recall()`, `check_contradictions()`,
etc.) accept `vector` without a dimension qualifier. PostgreSQL's pgvector will
reject dimension mismatches at runtime — if you pass a 768-dim vector to a table
with a `vector(3072)` column, the insert/query fails with a clear error.

### Impact on Tests

Test helpers use a constant (e.g., `const TEST_DIMS: usize = 768`) so tests can
be run against any dimension. The directional embedding helpers already work with
arbitrary dimensions — they just need the total dimension count as a parameter.

### Recommended Models

For agentic coding use cases (code snippets, architectural decisions, debugging
insights, technical documentation):

**Together.ai:** `Alibaba-NLP/gte-modernbert-base` (768 dims)
- 8,192 token context (16x more than bge-base's 512)
- Best code retrieval scores on the platform (79.31 COIR, 88+ CodeSearchNet)
- Highest MTEB retrieval score (55.33) despite being smaller than 1024-dim models
- $0.08/1M tokens (vs $0.01 for bge-base — negligible for memory workloads)

**OpenAI:** `text-embedding-3-large` (3072 dims, or 1024 truncated)
- Strong general-purpose performance
- Matryoshka representation learning allows dimension truncation without retraining

## Part 1: Typed Mnemes

### New Columns on `mnemes`

```sql
ALTER TABLE mnemes ADD COLUMN memory_type text NOT NULL DEFAULT 'factual'
    CHECK (memory_type IN ('factual', 'experiential', 'working'));
ALTER TABLE mnemes ADD COLUMN scope text NOT NULL DEFAULT 'personal'
    CHECK (scope IN ('personal', 'org'));
ALTER TABLE mnemes ADD COLUMN tier text NOT NULL DEFAULT 'index'
    CHECK (tier IN ('core', 'index', 'state'));
ALTER TABLE mnemes ADD COLUMN tags text[] NOT NULL DEFAULT '{}';
ALTER TABLE mnemes ADD COLUMN session_id uuid;
ALTER TABLE mnemes ADD COLUMN expires_at timestamptz;
```

### How Types Influence Cognitive Scoring

This is where pg_recall goes beyond Chapterhouse's current capabilities. Rather
than treating types as passive metadata filters, the scoring engine adapts its
behavior based on memory type — mirroring how real cognition handles different
kinds of knowledge differently.

#### Memory Type → Decay and Confidence Behavior

| Type | Ebbinghaus Stability | Contradiction Resistance | Rationale |
|------|---------------------|--------------------------|-----------|
| `factual` | Standard (14–365 days) | High — penalty threshold 0.10 (current default) | Facts should be stable and hard to displace. |
| `experiential` | Standard | Medium — penalty threshold 0.15 | Lessons learned are contextual; easier to revise. |
| `working` | Accelerated — stability cap at 48 hours | Low — penalty threshold 0.25 | Session context is ephemeral by design. |

**Implementation**: The `recall_inner()` function adjusts Ebbinghaus decay
parameters based on `memory_type`. Working memories use a hard stability cap
that forces rapid decay regardless of access frequency. The contradiction
resolution function reads `memory_type` to select the appropriate evidence
penalty.

#### Tier → Confidence Floor

| Tier | Confidence Floor | Effect |
|------|-----------------|--------|
| `core` | 0.30 | Core memories never drop below moderate confidence, even under contradiction. They require explicit deletion, not erosion. |
| `index` | 0.025 (current Laplace bound) | Standard behavior. |
| `state` | 0.025 | Standard behavior, but state mnemes are excluded from Hebbian learning. |

**Implementation**: `bayesian_update` checks the mneme's tier and clamps the
posterior to the tier's floor. State-tier mnemes are filtered out of
co-activation queue processing.

#### Scope → Recall Filtering

Scope filtering integrates with the existing `workspace_id` filter in recall:

- `personal` mnemes are only returned when the caller's user matches the creator.
- `org` mnemes are returned to any user in the same organization.

Since pg_recall operates at the SQL level without a session/auth context, scope
filtering is handled by adding an optional `scope` parameter to `recall()`. The
caller (Chapterhouse) passes the appropriate filter based on its auth context.

#### Session ID → Episodic Association

Mnemes sharing the same `session_id` form implicit associations. When a new
mneme is inserted with a `session_id`, a lightweight association (type `session`)
is automatically created to all other mnemes in the same session within the same
workspace.

This enables episodic recall — querying for one memory from a session
automatically boosts related memories from that same session via Hebbian scoring.

#### Working Memory Expiration

Working mnemes with `expires_at` set are automatically excluded from recall when
expired (`expires_at < now()`). The background worker's periodic maintenance adds
a new job: archive expired working memories (set `state = 'dormant'`).

#### Tags → Recall Filtering

Tags are exposed as an optional filter parameter on `recall()`. When provided,
only mnemes containing ALL specified tags are returned (AND semantics, matching
Chapterhouse's behavior).

### Indexes

```sql
CREATE INDEX mnemes_memory_type_idx ON mnemes (workspace_id, memory_type);
CREATE INDEX mnemes_session_id_idx ON mnemes (session_id) WHERE session_id IS NOT NULL;
CREATE INDEX mnemes_tags_idx ON mnemes USING gin (tags);
CREATE INDEX mnemes_expires_at_idx ON mnemes (expires_at) WHERE expires_at IS NOT NULL;
```

## Part 2: Typed Associations

### The Change

The current `associations` table has `(src_id, dst_id, weight, co_activations,
updated_at)` with a `CHECK (src_id < dst_id)` constraint enforcing canonical
ordering. All associations are anonymous Hebbian links.

v0.4 adds an `association_type` column and removes the `src_id < dst_id`
constraint to support directional relationships.

### Association Types

```sql
ALTER TABLE associations ADD COLUMN association_type text NOT NULL DEFAULT 'hebbian'
    CHECK (association_type IN (
        'hebbian',      -- co-activation link (existing behavior, undirected)
        'contradicts',  -- conflicting information (directed: src contradicts dst)
        'supersedes',   -- newer version of knowledge (directed: src replaces dst)
        'supports',     -- reinforcing evidence (directed: src supports dst)
        'session'       -- same-session context link (undirected, lightweight)
    ));
```

### Schema Change: Directional Associations

The `CHECK (src_id < dst_id)` constraint is removed. The primary key becomes
`(src_id, dst_id, association_type)` — the same pair of mnemes can have multiple
typed relationships (e.g., both a `hebbian` link from co-activation AND a
`contradicts` link from contradiction detection).

For **undirected** types (`hebbian`, `session`), canonical ordering is maintained
by convention in the insertion code: `src_id = LEAST(a, b)`,
`dst_id = GREATEST(a, b)`. This preserves the existing Hebbian learning code.

For **directed** types (`contradicts`, `supersedes`, `supports`), `src_id` is
the subject and `dst_id` is the object: "src contradicts dst", "src supersedes
dst", "src supports dst".

### How Types Are Created

| Type | Creation Mechanism |
|------|-------------------|
| `hebbian` | Existing co-activation batch processing (unchanged) |
| `contradicts` | `resolve_contradiction('confirmed')` creates a directed link |
| `supersedes` | Caller invokes new `mark_supersedes(newer_id, older_id)` function |
| `supports` | Caller invokes new `mark_supports(supporting_id, supported_id)` function |
| `session` | Automatic on insert when `session_id` matches other mnemes |

### How Types Influence Scoring

The `recall_inner()` function currently sums all association weights for Hebbian
boost. With typed associations, the boost calculation becomes type-aware:

```
hebbian_boost = sum(weight WHERE type = 'hebbian')
                + sum(weight WHERE type = 'supports') * 0.5
                + sum(weight WHERE type = 'session') * 0.3
                - sum(weight WHERE type = 'contradicts') * 0.5
```

- `hebbian` links contribute fully (existing behavior)
- `supports` links provide moderate boost (supporting evidence is helpful but
  less dynamic than co-activation)
- `session` links provide mild boost (episodic context is relevant but weak)
- `contradicts` links provide **negative** boost — contradicted mnemes are
  actively demoted in recall results, separate from the confidence penalty

`supersedes` links don't contribute to scoring directly. Instead, when a mneme
has an incoming `supersedes` link, its `state` is set to `archived` — it's
replaced, not just penalized.

### New Functions

#### `mark_supersedes(newer_id uuid, older_id uuid) -> text`

Creates a directed `supersedes` association from `newer_id` to `older_id`.
Sets the older mneme's state to `archived`. Returns `'ok'`.

#### `mark_supports(supporting_id uuid, supported_id uuid) -> text`

Creates a directed `supports` association. Optionally boosts the supported
mneme's confidence via `bayesian_update(confidence, 0.65)`. Returns `'ok'`.

#### `get_typed_associations(mneme_id uuid, association_type text DEFAULT NULL, min_weight float8 DEFAULT 0.01) -> SETOF ...`

Returns associations for a mneme, optionally filtered by type. Replaces or
extends the existing `get_associations()` function.

## Integration with Contradiction Detection (v0.3)

The contradiction system currently creates entries in `contradiction_candidates`
but does not create typed associations. v0.4 modifies `resolve_contradiction`:

- **confirmed**: in addition to the existing Bayesian penalty and association
  weakening, creates a `contradicts` association from mneme_a to mneme_b (or
  updates weight if one exists). This means the contradiction relationship is
  now visible in the association graph, not just in the candidates table.

- The `contradicts` association's weight is set to the cosine similarity from
  the candidate record — higher similarity = stronger contradiction signal.

## Updated `recall()` Signature

```sql
CREATE FUNCTION recall(
    workspace_id uuid,
    query_text text,
    query_embedding vector,               -- unqualified; dimension checked at runtime
    limit_n int DEFAULT 10,
    min_confidence float8 DEFAULT 0.0,
    weights pg_recall.score_weights DEFAULT NULL,
    memory_type text DEFAULT NULL,        -- new: filter by type
    scope text DEFAULT NULL,              -- new: filter by scope
    tags text[] DEFAULT NULL,             -- new: filter by tags (AND)
    session_id uuid DEFAULT NULL          -- new: filter/boost by session
) RETURNS SETOF pg_recall.recall_result
```

When `session_id` is provided, mnemes from that session receive an automatic
boost via session-type associations, even if no explicit Hebbian link exists.

## Background Worker Updates

The v0.2 background worker gains two new periodic jobs:

| Job | Interval | Action |
|-----|----------|--------|
| Working memory expiration | Every 10 minutes | Archive mnemes where `memory_type = 'working' AND expires_at < now()` |
| State mneme cleanup | Every 6 hours | Archive state-tier mnemes older than 24 hours with no recent access |

## Design Decisions

1. **Configurable embedding dimensions.** Different Chapterhouse deployments
   use different embedding models (768-dim gte-modernbert on Together.ai,
   3072-dim text-embedding-3-large on OpenAI in the corporate fork). The
   dimension is set once at initialization via `pg_recall.initialize(dims)` and
   cannot be changed without schema recreation. This avoids hardcoding a value
   that varies across deployments while keeping the extension Chapterhouse-specific.

2. **Directional associations.** Dropping `src_id < dst_id` enables natural
   relationship semantics ("A contradicts B" vs "B contradicts A"). Undirected
   types maintain canonical ordering by convention.

3. **Multiple association types per pair.** The same mneme pair can have both a
   `hebbian` link (from co-activation) and a `contradicts` link (from
   contradiction resolution). These are independent signals.

4. **Type-aware scoring in the extension.** Scoring adjustments happen in SQL
   functions, not in Chapterhouse Go code. This keeps the cognitive model
   cohesive and avoids splitting scoring logic across two codebases.

5. **Working memory expiration.** Handled by the background worker, not by
   the caller. Expired memories are archived, not deleted — they can be
   recovered if needed.

6. **No versioning in pg_recall.** Chapterhouse's `is_current` / `version`
   system is a higher-level concern. pg_recall treats each mneme as an
   independent entity. Version relationships are modeled via `supersedes`
   associations — the newer mneme supersedes the older one.
