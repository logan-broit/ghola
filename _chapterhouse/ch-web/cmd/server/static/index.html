Cognitive Primitives

Memory that adapts. Knowledge that evolves.

Context that sharpens through use, built on primitives modeled after how cognition actually works.

Typed Knowledge
Facts, experiences, and working context each behave differently. Standards persist. Lessons learned carry weight. Session notes fade naturally.
Adaptive Recall
Scoring blends semantic similarity, keyword matching, temporal recency, usage patterns, and confidence into a single relevance score. The right memory surfaces at the right time.
Session Continuity
Memories group by session. Resume where you left off, review what happened yesterday, or trace how a decision evolved across sessions.
Supersession
Knowledge evolves. When understanding changes, new memories supersede the old while preserving lineage. Your AI's knowledge stays current without losing history.
Hebbian Reinforcement
Memories recalled together strengthen together. Frequently useful knowledge rises to the top — the system learns what matters through use.
Temporal Decay
Unused memories naturally lose activation over time, keeping recall sharp. Working memories auto-expire after 7 days. Important knowledge persists through reinforcement.
Contradiction Detection
When new information conflicts with existing knowledge, the system identifies it. Contradictions surface rather than silently coexisting.
Organization Sharing
Personal memories stay private. Org memories share knowledge across your entire team. Change scope anytime.
On-Demand Context
Memories only enter context when recalled. No automatic injection means no wasted tokens — your AI pulls exactly what it needs.
How It Works

Three steps to persistent context

From conversation to searchable memory in milliseconds.

1
Remember
Your AI detects important context during conversation and stores it as a typed, tagged memory with scoped visibility.
"Remember that our API uses
snake_case for all JSON fields"
2
Store & Embed
The memory is embedded and stored in PostgreSQL via pg_recall. Full-text search, semantic vectors, and Hebbian scoring are all unified.
fact → pg_recall.mnemes
embedding → pgvector
tags → indexed & filterable
3
Recall
When context is needed, hybrid search finds the most relevant memories across all your sessions, filtered by tags and type.
"What are our API naming
conventions?"
→ recalls relevant facts
Protocol

9 tools. One protocol.

Memory management and session lifecycle through the Model Context Protocol.

Store a fact with optional tags, memory type, scope, and session ID. Proactively triggered when your AI learns something important.
{ "fact": "Our API uses snake_case for all JSON fields", "memory_type": "factual", "tags": ["api", "conventions"], "scope": "org", "session_id": "a1b2c3d4-..." }
Search across memories by meaning, keywords, or both. Filter by tags and memory type to surface the right context.
{ "query": "What are our API naming conventions?", "mode": "hybrid", "limit": 5 }
Remove a specific memory by its ID. Permanently deletes the fact from storage.
{ "fact_id": 42 }
Browse all stored memories with optional filtering by type, tags, or scope.
{ "memory_type": "factual", "tags": ["kubernetes"], "limit": 20 }
Change a memory's visibility between personal and org-wide. Only the creator can change scope.
{ "fact_id": 42, "scope": "org" }
Export memories to JSONL format for RAG ingestion, backup, or analysis.
{ "memory_type": "experiential", "tags": ["debugging"], "since": "2025-01-01T00:00:00Z" }
List recent sessions that created memories. Answer "what were we working on yesterday?" and find sessions to resume.
{ "limit": 10 }
Get a detailed breakdown of a session: memory count by type, tags used, time range, and truncated previews of each memory.
{ "session_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890" }
Resume where you left off. Loads all memories from a previous session, organized by type, for seamless context resumption.
{ "session_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890" }

Quick Start

Get started in 60 seconds

Add persistent memory and context management to your AI assistant.

Add Chapterhouse to Claude Code
claude mcp add -s user -t http chapterhouse \ https://ch.example.com/mcp/stateless \ --header "Authorization: Bearer ch_k1_your_api_key"
MCP server configuration (any compatible client)
{ "mcpServers": { "chapterhouse": { "type": "streamable-http", "url": "https://ch.example.com/mcp/stateless", "headers": { "Authorization": "Bearer ch_k1_your_api_key" } } } }
Deploy to Kubernetes with Helm
helm upgrade --install ch-server \ ch-server/charts/ch-server -n ch-system helm upgrade --install ch-web \ ch-web/charts/ch-web -n ch-system
