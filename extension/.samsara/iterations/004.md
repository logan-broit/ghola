# Iteration 4 (2026-04-11, samsara)

**What**: Deep analysis of multi-session retrieval failures (11.3% R@5). Attempted OR-based
FTS filter and two-pass AND-then-OR lexical pool. Both regressed severely.

**Hypothesis**: `plainto_tsquery` uses AND conjunction -- multi-session queries with 5-7 terms
exclude answer sessions matching most but not all. OR-based filter (spreading activation,
Collins & Loftus 1975) should admit partial matches.

**Approach A (pure OR)**: R@5 29.2% -> 12.4% (-16.8pp). OR filter admits 10K-16K sessions,
massive pool creates more ties, answer sessions pushed out.

**Approach B (AND priority, OR fallback)**: R@5 29.2% -> 10.6% (-18.6pp). OR fallback
computes cosine_sim for all OR-matching rows (~10K), queries 2-3x slower.

**Key insights**:
1. Multi-session retrieval is NOT a retrieval-time problem. Answer sessions are thematically
   indistinguishable from non-answer sessions at session level.
2. Broadening lexical filter (OR) hurts more than helps: precision loss > recall gain.
3. AND-based filter is correct for categories where it works. The problem is specific to
   multi-session where answer facts are fragments spread across sessions.
4. Multi-session requires ENCODING-TIME changes: multi-granularity storage or fact extraction.

**Reverted**: Yes, both approaches.
