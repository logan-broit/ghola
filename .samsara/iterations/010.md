# Iteration 10 (2026-04-12, samsara)

**What**: Encoding-time temporal enrichment -- add month name, day-of-week, season
tokens to the concept field during gating so the lexical pathway can match temporal cues.

**Hypothesis**: Adding temporal tokens (month name, day-of-week, season, year) to the
concept field (weight A in tsvector) enables the lexical pathway to match temporal
queries that reference "March", "Tuesday", "spring" etc. This should improve
temporal-reasoning R@5 by >2pp (the variance budget).

**Result**: REVERTED. Temporal tokens in concept field cause -4pp to -18pp regression
across ALL categories. Same mechanism as iters 4, 5, 9: common tokens shared by many
mnemes flood the lexical candidate pool, diluting precision.

## Neuroscience Grounding

Encoding specificity (Tulving, 1972): temporal context must be encoded at storage
time so retrieval cues can match. However, adding temporal tokens to the *general-purpose*
lexical field violates candidate pool purity (Iter 9 constraint). The correct application
is a *dedicated* temporal retrieval pathway (separate CTE on content_dates), not mixing
temporal cues into the general lexical search.

## Infrastructure Issues

Major infrastructure work was required before benchmarking:

1. **Corrupted database dumps**: The 20260412 binary COPY dumps had kubectl stderr
   ("Defaulted container...") mixed into the first 77 bytes. Fixed by `tail -c +78`.
   The 20260411 dumps were truncated (known from iter 7).

2. **Embedding server down**: The qwen3-embed vLLM server at 192.168.2.6:8082 was not
   running. The ch-server had been reconfigured to use TEI (nomic-embed-text-v1.5, 768d)
   but the pinned database has 1024d embeddings from qwen3 ingest. This caused
   "different vector dimensions 768 and 1024" errors on all recall queries.

3. **Fix**: Started a local sentence-transformers embedding server with
   Qwen3-Embedding-0.6B (1024d) and reconfigured ch-server to use it.

4. **Queue contamination**: Binary COPY fires INSERT triggers, re-populating gating and
   contradiction queues (18K+ items). Workers modify the database during benchmarks,
   causing massive variance (~16pp between identical runs). Fix: truncate all worker
   queues after COPY restore.

5. **Previous iter 10 agent re-embedded with wrong model**: A prior agent session
   re-embedded all mnemes with Qwen3 via sentence-transformers but the ch-server was
   using TEI (768d), creating a permanent mismatch. Restored from pinned dump to fix.

## Diagnosis (pre-implementation)

Analysis of temporal-reasoning failures (133 queries, baseline 23.3% R@5 from iter 9):
- 91/104 misses have GT not in top-10 at all -- candidate generation failure
- Session timestamps use `[timestamp: 2023/05/28 (Sun) 04:55]` format
- `extract_dates()` only matched YYYY-MM-DD, missing all YYYY/MM/DD timestamps
- PostgreSQL tsvector produces abbreviated day names (`sun`) not full (`sunday`)
- Full month names absent from tsvector entirely

## Implementation

1. **Fixed `extract_dates()`**: Now handles both YYYY-MM-DD and YYYY/MM/DD formats,
   normalizing all dates to YYYY-MM-DD. Genuine bug fix, kept.

2. **Added `temporal_tokens_from_date()`**: Converts date to "march wednesday spring 2023".
   Uses Tomohiko Sakamoto's algorithm for day-of-week. Kept as utility.

3. **Added `extract_temporal_tokens()`**: Parses `[timestamp:]` header. Kept as utility.

4. **Modified gating worker**: Appended temporal tokens to concept enrichment.
   **REVERTED** -- harmful per benchmark results.

5. **Migration SQL**: Applied temporal tokens to 18910 existing mnemes via batched
   UPDATEs with SKIP LOCKED. **Effect was harmful, restored from pinned dump.**

## Key constraints discovered

- **Corrupted COPY dumps**: kubectl stderr mixes into stdout on `kubectl exec ... COPY TO`.
  Fix: `kubectl exec ... 2>/dev/null` or post-hoc `tail -c +78` to strip 77-byte prefix.
  Both 20260411 and 20260412 dumps were affected.
- **Binary COPY fires INSERT triggers**: Restoring via COPY binary populates gating and
  contradiction queues (18K+ items). Workers modify DB during benchmarks. Must TRUNCATE
  all queues post-restore.
- **Temporal tokens in concept field dilute lexical pool**: Month names match ~1500 mnemes
  each, season names match ~4700. Adding these to weight-A tsvector floods the lexical
  candidate pool (same mechanism as iters 4, 5, 9).
- **Dedicated temporal pathway needed**: Temporal context should be in a SEPARATE retrieval
  CTE (using content_dates), not mixed into the general lexical search.
- **Embedding server instability**: vLLM qwen3-embed on workstation is ephemeral.
  sentence-transformers fallback has higher benchmark variance (8pp vs 2pp).
- **ch-server embedding config was changed post-iter-9**: From qwen3/1024d to TEI/768d,
  creating dimension mismatch with stored 1024d embeddings. Must keep config consistent.

## What to try next

1. **Temporal retrieval pathway** (moderate effort): A dedicated CTE that matches
   queries against content_dates. Keeps temporal matching separate from the general
   lexical pool, preserving candidate purity. This is the correct application of
   encoding specificity for temporal cues.

2. **Query decomposition** (stashed in git stash, recall.rs changes): Decompose
   multi-event queries ("between X and Y") into per-event sub-queries. Each sub-query
   gets its own FTS CTE. Additive pathway -- can only add candidates. Already
   implemented and stashed in `iter-11-query-decomposition`.
