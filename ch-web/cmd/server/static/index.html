Capabilities

Intelligent memory, managed context

Semantic search, typed memories, filtered recall, organization sharing, and enterprise-grade security.

Hybrid Search
Vector embeddings find memories by meaning, keyword search finds exact matches. Hybrid mode fuses both with reciprocal rank fusion for the best results.
Memory Types
Factual for standards, experiential for lessons learned, and working for session context that auto-expires in 7 days.
Organization Sharing
Personal memories stay private. Org memories share knowledge across your entire team. Change scope anytime.
Tagged & Filtered Recall
Categorize memories with tags and types. Filter recall by project, technology, or memory classification to surface precisely the right context.
On-Demand Context
Memories only enter context when recalled. No automatic injection means no wasted tokens — your AI pulls exactly what it needs, when it needs it.
6 MCP Tools

Enterprise Ready

Self-Hosted

How It Works

Three steps to persistent context

From conversation to searchable memory in milliseconds.

1
Remember
Your AI detects important context during conversation and stores it as a typed, tagged memory with scoped visibility.
"Remember that our API uses
snake_case for all JSON fields"
2
Store & Embed
The memory is stored in PostgreSQL. A vector embedding is generated and indexed in Qdrant for search.
fact → PostgreSQL
embedding → Qdrant
tags → indexed & filterable
3
Recall
When context is needed, hybrid search finds the most relevant memories across all your sessions, filtered by tags and type.
"What are our API naming
conventions?"
→ recalls relevant facts
Protocol

6 tools. One protocol.

A complete memory API through the Model Context Protocol.

Store a fact with optional tags, memory type, and scope. Proactively triggered when your AI learns something important.
{ "fact": "Our API uses snake_case for all JSON fields", "memory_type": "factual", "tags": ["api", "conventions"], "scope": "org" }
Search across memories by meaning, keywords, or both. Filter by tags and memory type to surface the right context.
{ "query": "What are our API naming conventions?", "mode": "hybrid", "limit": 5 }
Remove a specific memory by its ID. Permanently deletes the fact from storage.
{ "fact_id": 42 }
Browse all stored memories with optional filtering by type, tags, or scope.
{ "memory_type": "factual", "tags": ["kubernetes"], "limit": 20 }
Change a memory's visibility between personal and org-wide. Only the creator can change scope.
{ "fact_id": 42, "scope": "org" }
Export memories to JSONL format for RAG ingestion, backup, or analysis.
{ "memory_type": "experiential", "tags": ["debugging"], "since": "2025-01-01T00:00:00Z" }

Quick Start

Get started in 60 seconds

Add persistent memory and context management to your AI assistant.

Add Chapterhouse to Claude Code
claude mcp add -s user -t http chapterhouse \ https://chapterhouse.switchcraft.pd.internal/mcp/stateless \ --header "Authorization: Bearer ch_k1_your_api_key"
MCP server configuration (any compatible client)
{ "mcpServers": { "chapterhouse": { "type": "streamable-http", "url": "https://chapterhouse.switchcraft.pd.internal/mcp/stateless", "headers": { "Authorization": "Bearer ch_k1_your_api_key" } } } }
Deploy to Kubernetes with Helm
helm upgrade --install ch-server \ ch-server/charts/ch-server -n ch-system helm upgrade --install ch-web \ ch-web/charts/ch-web -n ch-system
